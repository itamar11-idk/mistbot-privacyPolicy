MistBot Privacy Policy

Last Updated: June 14, 2026

1. Scope

This Privacy Policy applies to MistBot's Discord bot features only.

MistBot is a community tool for Attack on Titan: Revolution players. This policy explains what data MistBot processes through Discord, how it is used, when it is shared, and how you can request access, correction, or deletion.

2. Data We Process

2.1 Data You Provide Through Commands or Messages

  • Vouch data: vouch submissions, carrier identity, vouch type, totals, and related metadata.
  • Marketplace data: listing text (giving/looking for), optional notes, your Discord user ID, Discord username, and listing status. Listings are also broadcast to all servers subscribed to the global marketplace feed via Discord webhooks.
  • Safety data: scam reports, blacklist appeals, descriptions, and evidence attachments you submit.
  • Lobby data: lobby settings, participant lists (Discord user IDs), host information, and temporary private server codes if you post them.
  • Prefix and slash commands: all commands you issue (both ,command style and /command style) are processed, and basic metadata (command name, user ID, guild ID, timestamp) is logged for operational purposes.

2.2 Data From Discord APIs or Bot Events

  • Account identifiers: Discord user ID, username/display name, and avatar URL.
  • Server context: guild/server IDs, channel IDs, role IDs, and configuration needed for per-server behavior.
  • Message content in configured trade channels: Mist-Connect scans trade-channel messages to detect trade intent. This content is sent to Groq's AI API for parsing. Detected trade offers are stored as ghost listings.
  • Message content in lobby private channels: the lobby system reads messages in private lobby channels to detect "code" or "password" queries so it can automatically share the server join code.
  • Message content for promotion-reminder completion: in servers with promotion reminders enabled, the bot reads messages in the configured channel to detect "done" replies.
  • Operational metadata: timestamps, command usage, error/health telemetry, and anti-abuse/rate-limit data.

2.3 Data We Do Not Intentionally Collect

  • Passwords or external login credentials.
  • Payment card or banking data.
  • Message content outside bot-relevant contexts, except where required by Discord interactions or explicitly configured channel monitoring.

3. Why We Use Data

We process data to:

  • Operate bot commands and features, including both prefix and slash commands.
  • Track vouches, profiles, and leaderboards.
  • Publish and manage marketplace listings, including cross-server syndication.
  • Detect likely trade posts in configured trade channels.
  • Run scam-reporting, blacklist, and appeal workflows.
  • Prevent abuse, enforce cooldowns/rate limits, and maintain service reliability.
  • Manage game lobbies with code sharing and participant tracking.
  • Send hourly operational reports to staff for abuse detection.

5. Sharing Rules

We do not sell personal data.

We share data only when needed to run MistBot, including:

  • With service providers listed in this policy to operate bot features.
  • Across MistBot-enabled servers where a feature is intentionally global (for example, global marketplace feed and global blacklist enforcement). This means a listing you post or a blacklist action taken against you applies to all servers using the bot.
  • When required by law or legal process.
  • When a user explicitly directs sharing through a bot feature.

6. Storage and Security

  • Primary datastore: MongoDB Atlas. All persistent bot data (guild configs, marketplace listings, vouches, blacklists, lobbies, builds, appeals, trade stats, notifications, and command logs) is stored in a MongoDB Atlas cluster secured with authentication and network access controls.
  • In-memory caches: command rate-limit tracking, recent-command spam detection, listing cooldowns, guild configuration, and item value lookups are held temporarily in memory and reset on bot restart or cache expiry (typically minutes to 24 hours depending on the cache).
  • Local log files: command usage logs are written to logs/commands.jsonl on the bot's server, rotated at 500KB with up to 6 backup files retained for operational monitoring.
  • Google Sheets: used only for item value reference data (read-only; no user PII is stored in Google Sheets).
  • Access to all systems is restricted to maintainers and authorized services.
  • We use reasonable technical and organizational measures to reduce unauthorized access risk.

Note: No system can guarantee absolute security.

7. Retention

Retention depends on feature purpose:

  • Marketplace listings: generally expire automatically after 6 hours; ghost/verification trade drafts expire after approximately 24 hours.
  • Lobbies: removed after closure/timeout.
  • Command logs (MongoDB): automatically deleted after 24 hours (TTL index).
  • Command logs (JSON files): rotated when the active file reaches 500KB; up to 6 backup files are retained (automatically deleted after maximum of 30 days).
  • In-memory caches: rate-limit tracking data is held for the duration of the rate-limit window.
  • Vouches, blacklist, appeals, and moderation records: retained until removed, reset, overturned, or no longer needed for the stated purpose. Vouch records are maintained as long as the user is an active participant in the community to ensure leaderboard integrity, but can be wiped upon a valid deletion request.
  • Operational logs/caches: short-lived where possible; some system records may persist for reliability or abuse prevention.

We delete or update data when it is no longer necessary for stated functionality, when legally required, or when a valid user request applies.

8. Access, Correction, and Deletion Requests

You can request to access, correct, or delete your MistBot-related data.

How to request:

  • Open a ticket in the support server.
  • Include your Discord user ID and the request type: access, correction, or deletion.

We provide an accessible request path and will handle valid requests within a reasonable timeframe, subject to legal and safety obligations.

Feature-specific controls may also be available in bot commands (for example, deleting listings via /listings or submitting blacklist appeals via ,appeal).

9. Discord Developer Terms Alignment

This policy is intended to align with Discord Developer Terms requirements for privacy and security, including:

  • Clear disclosure of collection, use, sharing, and retention.
  • Public availability of a privacy policy.
  • A user-accessible method to request data modification/deletion.
  • Limiting third-party sharing to service providers, legal requirements, or user-directed actions.

If Discord requests data update/deletion related to API data, we will comply as required by applicable terms and law.

10. Children's Privacy

MistBot is intended only for users who meet Discord's minimum age and legal requirements in their region. We do not knowingly collect personal data from children under the applicable minimum age.
